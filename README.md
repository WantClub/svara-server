# СВАРА — клуб для игры на фишки

Полноценный сайт: регистрация игроков, кошелёк фишек, стол на 6 игроков
с настоящей real-time синхронизацией (WebSocket), и админ-панель для владельца.

## Что внутри

- **server.js** — сервер (Express + Socket.io). Единственный источник правды:
  хранит все карты и решает, чей ход — клиенты не могут подсмотреть чужие руки
  или сжульничать через консоль браузера, как это было бы в чисто клиентской версии.
- **game.js** — правила игры в Свару (раздача, ставки, сравнение комбинаций).
- **db.js** — база данных SQLite (файл `svara.db`, создаётся автоматически).
- **public/index.html** — весь клиентский интерфейс (один файл).

## Как это работает

- Первый, кто зарегистрируется на сайте — автоматически становится админом.
- У каждого игрока — кошелёк (число фишек), который меняет только админ вручную
  через панель. Онлайн-оплаты на сайте нет — это осознанное решение (см. предыдущее
  обсуждение про лицензирование азартных игр).
- Админ видит список всех игроков, их баланс, может пополнять/списывать фишки,
  банить/разбанивать, назначать других админов.
- Админ может открыть любой активный стол и увидеть карты **всех** игроков в
  реальном времени, не садясь за стол сам (раздел «Активные столы — наблюдение»).
- Игроки создают столы или заходят по коду, делают бай-ин из своего кошелька,
  играют (ставка/подъём/пас), при выходе из-за стола остаток фишек возвращается
  в кошелёк.

## Запуск локально (для проверки)

Нужен установленный Node.js (18+).

```bash
cd svara-server
npm install
cp .env.example .env
# откройте .env и замените JWT_SECRET на свой случайный ключ
node server.js
```

Откройте `http://localhost:3000` в браузере.

## Как выложить в интернет (чтобы был доступен всем)

Проще всего — бесплатные хостинги для Node.js с постоянным диском:

### Вариант: Render.com
1. Зарегистрируйтесь на render.com, подключите GitHub-репозиторий с этим кодом
   (или загрузите файлы напрямую, если Render это поддерживает в вашем плане).
2. New → Web Service → укажите папку проекта.
3. Build Command: `npm install`
4. Start Command: `node server.js`
5. В разделе Environment добавьте переменную `JWT_SECRET` со своим случайным
   значением (сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`).
6. **Важно:** бесплатный тариф Render использует временный диск — файл
   `svara.db` может обнуляться при передеплое/перезапуске контейнера.
   Чтобы данные не терялись, либо подключите Render Disk (платно), либо
   на старте используйте PostgreSQL (см. ниже — могу переписать под него).

### Вариант: Railway.app
Похожая схема: подключаете репозиторий, задаёте `JWT_SECRET`, Railway
даёт постоянный volume для файла базы данных на бесплатном тарифе с лимитом часов.

## Если понадобится PostgreSQL вместо SQLite

Файловая база (SQLite) отлично работает для клуба на десятки-сотни игроков,
но на некоторых бесплатных хостингах файл может не переживать передеплой.
Если это станет проблемой — дайте знать, я перепишу `db.js` под бесплатный
PostgreSQL (Render/Railway оба дают бесплatный тариф с постоянным хранением) —
остальной код (server.js, game.js, клиент) менять не придётся.

## Важно про безопасность

- Пароли хранятся хэшированными (bcrypt), не в открытом виде.
- Игра теперь по-настоящему честная: сервер — единственный, кто знает все
  карты, обычный игрок технически не может увидеть чужую руку.
- Обязательно замените `JWT_SECRET` в `.env` перед реальным запуском —
  значение по умолчанию известно из этого кода и не защищает токены входа.
- На сайте нет приёма реальных денег — это специально, чтобы не попадать
  под регулирование азартных игр (см. обсуждение в чате).
